# StarTracker — จอ CYD + BNO055 + LX200 TCP

โค้ดอยู่ในโฟลเดอร์ Main ที่ระบุไว้ ใช้ PlatformIO เปิดโฟลเดอร์นี้แล้ว Build/Upload
ไลบรารีทัชรวมอยู่ใน `lib/XPT2046_Touchscreen` แล้ว ไม่ต้องติดตั้ง Git
เมื่อติดตั้งจาก ZIP ต้องแตกทั้งโฟลเดอร์ Main รวมโฟลเดอร์ lib และใช้ platformio.ini ที่มาพร้อมกัน
ไฟล์ต้นฉบับภาพและฟอนต์เดิมยังอยู่ครบ ไม่ได้แก้โปรเจกต์ Master หรือ CYD_Slave

## การแก้ไขรอบทัชและเข็มทิศ

แก้ `Display buffer allocation failed`: วาดเป็นแถบ RGB565 320×40 ใช้ข้อมูลภาพ
25,600 ไบต์ แทนบัฟเฟอร์เต็มจอ 153,600 ไบต์ ถ้าจัดสรรไม่ได้จะลดความสูงแถบเป็น
20 หรือ 10 แถว โดยยังคงสี 16 บิต ขนาด ฟอนต์ และตำแหน่งเดิม
เพิ่ม BandCanvas.h เพื่อแปลงพิกัด/ตัดขอบภาพแต่ละแถบ และตรึงเฟรมแอนิเมชันตลอดการวาดหนึ่งจอ
แก้ใน Main แล้ว ให้ Build/Upload ใหม่ ไม่มีการล้างค่าคาลิเบรตทัชที่บันทึกไว้

- คืนป้าย RA/DEC เป็น Org_01 ขนาด 4 ที่ (170,131)/(146,167), สี 0x05FA
- คืนเวลาเป็น Org_01 ขนาด 2 ที่ (231,67), สี 0xF206
- คืนภาพพื้นหัวจอและไอคอนเดิมทุกขนาด/ตำแหน่ง
- คืนโลโก้ compass_32_32_28f ที่ (2,61), 32×32, สี 0x04B1, 28 เฟรม/42ms
- วงเข็มทิศยังอยู่ในขอบเขต 105×83 ที่ (28,106) ใช้สีขาวเดิม ลูกศรสี 0xFE00
- ลูกศรชี้หน้าคงที่ N/E/S/W หมุนตามมุม IMU
- ค่าตัวเลข RA/DEC ที่เพิ่มใหม่ใช้ Org_01 ขนาด 2 เพื่อวางข้างป้ายเดิมได้โดยไม่ย่อป้าย
- ใช้ RGB565 16 บิตตลอด ไม่ลดเป็น 8 บิตเมื่อหน่วยความจำไม่พอ

## สิ่งที่ทำแล้ว

- หน้าเปิดเครื่อง: ดาว 5 ดวงค่อย ๆ ปรากฏและลอยขึ้นจากซ้ายไปขวา แล้วบาร์จึงเริ่มโหลด ก่อนเข้าหน้าหลัก
- หน้าหลัก: รูปปุ่มจาก Lopaka, เข็มทิศวงแหวน 3 มิติหมุนตาม BNO055 โดยลูกศรกลางอยู่นิ่ง, RA/DEC, เวลา, Wi-Fi และแบตเตอรี่
- ปุ่มบน: บ้าน = หน้าหลัก, พระจันทร์ = หรี่ไฟ (คงสีต้นฉบับ), ดาว = แค็ตตาล็อก, เฟือง = การตั้งค่า, N/S = พิกัดสถานที่
- รายการดาว: ลากขึ้นลงได้ กดหมวด ALL / CONST / CLUST / GALAX / NEB ด้านซ้าย กดลูกศรเพื่อกลับ
- เลือกรายการแล้วอ่านข้อมูลเป้าหมายจาก LX200 ก่อนเปิดใช้ START? ส่งคำสั่งเคลื่อนกล้องเมื่อกด START? เท่านั้น มี STOP
- ไอคอนค้นหา Wi-Fi ใช้ 28 เฟรมเดิม เมื่อมีไคลเอนต์ AP จะหยุดเคลื่อนไหวและเปลี่ยนเป็นขีด RSSI
- แบตต่ำกว่า 15% เปลี่ยนเป็นสีแดงส้มและกระพริบ เมื่อชาร์จใช้แอนิเมชันเดิม
- ตั้งค่าพิกัด มุมชดเชย และ IP/พอร์ตในมือถือ บันทึกลง NVS

## เริ่มใช้งาน

1. เปิด Main ใน PlatformIO และกด Build จากนั้น Upload ไปยังบอร์ดที่เลือกเอง
2. มือถือเชื่อม Wi-Fi `StarTracker` รหัส `startrack24`
3. เปิด `http://192.168.4.1` เวลาจะถูกส่งจากมือถือให้อัตโนมัติเมื่อเปิดหน้าเว็บ
4. กรอก latitude/longitude (ทิศใต้เป็นลบ ตะวันออกเป็นบวก) แล้วบันทึก N/S เปลี่ยนตาม latitude
5. ตั้ง IPv4 และ TCP port ของ LX200 จริง ค่าเริ่มต้นช่อง port คือ 4030 และ IP เว้นว่าง ไม่ได้สมมติว่าเชื่อมแล้ว
6. อุปกรณ์ LX200 TCP ต้องเชื่อมเข้า AP StarTracker เช่นเดียวกับมือถือ หาก LX200 เปิด AP ของตัวเอง ต้องปรับเป็น AP+STA เพิ่มเติมก่อน โค้ดชุดนี้ใช้ AP อย่างเดียว
7. คาลิเบรต BNO055 เทียบทิศเหนือจริงและแนวกล้อง แล้วใส่มุมชดเชยและติ๊กช่อง alignment
8. เปิดแค็ตตาล็อก แตะเป้าหมาย รอข้อมูลจาก LX200 และกด START? หากต้องการเริ่มงาน

การเชื่อม Wi-Fi เพียงอย่างเดียวไม่ส่งเวลามือถือ ต้องเปิดหน้าเว็บข้างต้นอย่างน้อยหนึ่งครั้งหลังเปิดเครื่อง
นาฬิกาใช้ UTC ภายในและแสดง offset ตามมือถือ ไม่มี RTC สำรองหรือ NTP ในโหมดนี้
หากเปลี่ยนเขตเวลา/DST ให้เปิดหน้าเว็บหรือตั้งเวลาอีกครั้ง

## IMU และ RA/DEC

ใช้โครงจากผู้ใช้: `Adafruit_BNO055(55, 0x29, &Wire)`, `Wire.begin(27,22)`,
`bno.getEvent(&event)`, `setExtCrystalUse(true)` และมุม x=yaw, y=roll, z=pitch
วงเข็มทิศใช้ yaw/pitch/roll จากตัวอย่างเพื่อแสดงมุมมอง 3 มิติ พร้อม perspective
N/E/S/W อยู่บนแกนทิศจริงและหมุนสวน heading ของเครื่อง ลูกศรกลางชี้ขึ้นด้านหน้าเสมอ

RA/DEC ไม่เท่ากับค่า yaw/pitch โดยตรง โค้ดแปลง azimuth/altitude เป็นพิกัด equatorial
ด้วยเวลา UTC และพิกัดสถานที่ โดยสมมติแกน +X ของ IMU ชี้ตามแนวกล้อง
ใช้ `azimuth = yaw + azOffset`, `altitude = -pitch + altOffset`
ต้องตรวจเครื่องหมายมุมและแนวติดตั้งจริง หากติดตั้งคนละแกนให้เปลี่ยน axis mapping
แสดงค่าเมื่อมีเวลา พิกัด และยืนยัน alignment ค่า calibration ดูได้ใน Settings
หาก magnetometer ยังไม่คาลิเบรต ค่าทิศและ RA/DEC จะคลาดเคลื่อนได้ แต่ไม่บล็อกการแสดงค่า
ค่าที่ได้เป็น IMU estimate ไม่รวม refraction, precession หรือโมเดลแก้ความคลาดของ mount
หากต้องการความแม่นยำสำหรับงานติดตาม ให้ใช้ระบบ alignment/encoder ของ mount เพิ่มเติม

## LX200 และข้อมูลดาว

แค็ตตาล็อกที่แสดงเป็นดัชนีตัวอย่างใน `Catalog.h` จำนวน 25 รายการ ไม่ใช่การดาวน์โหลดฐานข้อมูลทั้งหมด
หมวด CONST เป็นพื้นที่หมู่ดาว แต่เป้าหมายที่สั่งเคลื่อนเป็นวัตถุตัวแทนที่ระบุชัด เช่น Orion → M42
หมวด CLUST เป็นกระจุกดาว ไม่ใช่ดาวฤกษ์เดี่ยว สามารถเพิ่มรายการ Messier ในไฟล์นี้ได้

ลำดับอ่าน: `:LMnnnn#` → `:LI#` → `:Gr#` → `:Gd#`
ลำดับเริ่ม: `:Sr...#` รอ `1` → `:Sd...#` รอ `1` → `:MS#` รอ `0`
ตั้งพิกัดที่อ่านมาอีกครั้งก่อนเริ่ม เพื่อไม่ใช้เป้าหมายที่ถูกเปลี่ยนโดยไคลเอนต์อื่นก่อนกด START
STOP ส่ง `:Q#` ซึ่งโปรโตคอลไม่มีคำตอบยืนยัน จึงแสดงว่า “ส่งคำสั่งแล้ว” เท่านั้น
`Slew accepted` หมายถึง mount รับคำสั่ง ไม่ใช่รายงานว่าถึงเป้าหมายแล้ว

คำสั่งแค็ตตาล็อกไม่ใช่ส่วนที่ทุก firmware แบบ LX200-compatible รองรับ
ชุดนี้ต้องใช้ mount ที่รองรับ Messier library และคืนข้อมูลเป้าหมายจริง
Meade บางรุ่นคืนข้อมูล `:LI#` แบบคงที่; OnStep/เฟิร์มแวร์ทำเองอาจไม่มี library เลย
ต้องยืนยันความสามารถกับเฟิร์มแวร์จริงก่อนใช้ข้อมูลเป้าหมาย ไม่ถือว่าการเชื่อม TCP สำเร็จแปลว่ารองรับคำสั่งทั้งหมด
ถ้าเฟิร์มแวร์ไม่รองรับ ต้องเพิ่ม catalog adapter/พิกัดดาวให้ตรงระบบ โค้ดไม่เดาพิกัดสำรองเมื่อคำสั่งล้มเหลว

อ้างอิง: [Meade Telescope Serial Command Protocol Revision L](https://aggregate.org/DIT/CAPTURE/LX200CommandSet.pdf)

## แบตเตอรี่ที่มี BMS

BMS ที่ไม่มีช่อง telemetry ไม่ได้ส่งเปอร์เซ็นต์หรือสถานะชาร์จให้ ESP32 โดยอัตโนมัติ
จึงตั้ง `BATTERY_ADC=-1`, `CHARGE_PIN=-1` และแสดง `--%` ในตอนนี้
ไม่ได้แต่งค่าเปอร์เซ็นต์ และไม่ถือว่าการเสียบ USB เท่ากับกำลังชาร์จแบต

หากเพิ่มวงจรวัดแรงดัน ให้ตั้งค่าต่อไปนี้ใน Config.h:

- `BATTERY_ADC`: ขา ADC1 ที่ว่างจริงบนบอร์ด; ADC2 ใช้ร่วม Wi-Fi ไม่เหมาะ
- `BATTERY_DIVIDER`: อัตราส่วนวงจรแบ่งแรงดันที่ติดตั้งจริง
- `BATTERY_EMPTY` / `BATTERY_FULL`: แรงดันตามชนิดและจำนวนเซลล์จริง
- `CHARGE_PIN` / `CHARGE_ACTIVE`: สัญญาณจากชาร์จเจอร์/วงจรวัดที่ให้สถานะชาร์จจริง

ค่า 3.3–4.2V และ divider 2 เป็นค่าเริ่มต้นของตัวอย่างเท่านั้น ยังไม่ใช่ค่าของแพ็กผู้ใช้
วงจรแบ่งแรงดันต้องทำให้แรงดัน ADC ไม่เกินขอบเขตของ ESP32 และห้ามต่อแบตเข้าขา ADC ตรง ๆ
เปอร์เซ็นต์จากแรงดันแบบเส้นตรงเป็นค่าประมาณ ควรใช้ fuel gauge หากต้องการเปอร์เซ็นต์แม่นยำ

## พินและสัมผัส

- TFT ILI9341: MISO12 / MOSI13 / CLK14 / CS15 / DC2 / BL21 ใช้ HSPI
- XPT2046: MISO39 / MOSI32 / CLK25 / CS33 / IRQ36 ใช้ VSPI แยกจากจอ
- BNO055: SDA27 / SCL22 / address 0x29
- หน้าจอ landscape 320×240, rotation 1

ใช้ไลบรารี XPT2046_Touchscreen 1.4 แบบ polling โดยไม่บังคับให้ IRQ เป็น LOW
แยก SPI จอเป็น HSPI และทัชเป็น VSPI มีการอ่านแรงกดและกรอง ADC noise

เมื่ออัปโหลดรุ่นนี้ครั้งแรก หลังหน้าโหลดจะเข้า TOUCH CALIBRATION:

1. กดกากบาทค้างประมาณครึ่งวินาทีจนมีวงสีเขียว แล้วปล่อย
2. ทำตามกากบาท 3 จุด (ซ้ายบน → ขวาบน → ล่างกลาง)
3. จุดที่ 4 ตรงกลางเป็นการตรวจความแม่นยำ เมื่อผ่านจะเข้าหน้าหลักและบันทึก NVS

ระบบเรียนรู้การสลับแกน/กลับแกนเอง ไม่ต้องเดาค่า min/max
ปุ่มเมนูทำงานหลังปล่อยนิ้ว; การลากรายการไม่ถือเป็นการเลือกดาว
หากต้องคาลิเบรตใหม่ ใช้ปุ่ม CALIBRATE TOUCH ในหน้า Settings,
ปุ่มคาลิเบรตในเว็บมือถือ หรือส่งตัวอักษร C ทาง Serial Monitor ที่ 115200 baud
ไม่จำเป็นต้องล้างค่า Wi-Fi/พิกัดที่บันทึกไว้
หากแม้แต่กากบาทไม่ตอบสนอง ต้องตรวจรุ่นชิปทัช/การเชื่อมต่อจริงเพิ่มเติม
สเปก ILI9341 ระบุเฉพาะชิปแสดงผล ไม่ได้ยืนยันชิปทัชของทุกรุ่น
ข้อความเตือนของ TFT_eSPI ว่า TOUCH_CS ไม่ได้กำหนดเป็นปกติ เพราะใช้ตัวอ่าน XPT2046 แยกต่างหาก
ไม่ได้ใช้ `tft.getTouch()` ซึ่งผูกกับ SPI ของ TFT

## การทดสอบ

ผ่าน Build ESP32 ด้วย PlatformIO และทดสอบ C++ บนคอมพิวเตอร์:
ทิศทางแกนทัช 8 แบบ, ตำแหน่งปุ่มเมนู, tap/swipe/noise, N/E/S/W ที่ heading 0/90/180/270,
พิกัดอ้างอิง J2000, ค่าขอบเขต RA/DEC, ไม่ส่ง :MS# ก่อน START,
รับคำตอบแบบหนึ่งไบต์, คำสั่งถูกปฏิเสธ, timeout, cancel, ขาดการเชื่อมต่อ และ STOP

รันทดสอบจากโฟลเดอร์ Main (ต้องมี g++):

```powershell
g++ -std=c++17 -I tests/fakes tests/core_tests.cpp -o core_tests.exe
.\core_tests.exe
```

ยังไม่ได้แฟลชบอร์ดหรือทดสอบจอสัมผัส, ค่าแกน IMU, RAM ขณะทำงานจริง, TCP ของ mount และวงจรแบตจริง
ก่อนใช้งานจริง ตรวจว่าทัชตรงตำแหน่ง วงแหวนหมุนถูกแกน และชื่อ/พิกัด LX200 ตรงกับเป้าหมายที่เลือก
